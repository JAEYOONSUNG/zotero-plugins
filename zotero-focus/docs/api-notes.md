## Columns and lifecycle

`chrome/content/zotero/xpcom/pluginAPI/itemTreeManager.js`:

- `Zotero.ItemTreeManager.registerColumn(option) -> string | false`. Required strings: `dataKey`, `label`, `pluginID`. Save the returned key, which is namespaced and can differ from the input. A false return is registration failure.
- `unregisterColumn(returnedDataKey) -> boolean`; `refreshColumns() -> void`. Plural `registerColumns` / `unregisterColumns` are deprecated wrappers.
- Use `enabledTreeIDs: ['main']` (also the default); `['*']` opts into every item tree. `defaultIn` / `disableIn` are deprecated.
- `dataProvider(item, dataKey) -> string`; keep it synchronous and inexpensive. `renderCell(index, data, column, isFirstColumn, doc) -> HTMLElement`. Create elements with the supplied document, assign `cell.className = 'cell ' + column.className`, and use `textContent` for tag strings. The renderer checks `cell instanceof window.Element` and falls back on an invalid result (`itemTree.js:3272`).
- Runtime validation requires **`width` to be a string**, despite a number appearing in the bundled JSDoc example. `minWidth` and `flex` are numbers; `fixedWidth`, `staticWidth`, `showInColumnPicker`, `columnPickerSubMenu`, `noPadding` are booleans. `zoteroPersist` accepts an array, such as `['width', 'hidden', 'sortDirection']`.
- `pluginAPIBase.mjs:312` namespaces keys using `CSS.escape(pluginID + '-' + dataKey)`. The manager automatically removes registrations on plugin shutdown (`:340–373`); explicit cleanup remains useful for partial startup failures and hot reload.

`chrome/content/zotero/xpcom/preferencePanes.js:102–200`:

- `await Zotero.PreferencePanes.register({pluginID, src, id?, label?, scripts?, stylesheets?, image?, helpURL?}) -> paneID`.
- `Zotero.PreferencePanes.unregister(paneID)` removes the pane and refreshes open preferences windows. Registering requires both `pluginID` and `src`. Scripts and stylesheets default to empty arrays; resource paths can be relative to the extension root.
- Plugin shutdown also automatically unregisters the plugin's panes. Explicitly remove plugin-owned window listeners, styles, timers, and DOM nodes; manager cleanup does not cover them.

## Native title cells and hover scrolling

Sources: `chrome/content/zotero/itemTree.js:1206–1223,3100–3180,3272–3402`; `chrome/content/zotero/components/virtualized-table.js:940–963,1122–1154,1230–1270`.

- Stable outer mount: `#zotero-items-tree`. The inner table ID is `item-tree-main` plus an optional view visibility suffix. Do not assume it is `main` or constant across collection views.
- Ordinary title target: `#zotero-items-tree .row .cell.title .cell-text`. The title cell additionally has `primary`; whichever column is first gets `first-column` and prepended indentation, twisty, and icon elements.
- The `.cell-text` title can contain rich inline markup generated by `renderItemTitle()`. Its `aria-label` also includes item type and tag information. Preserve both; do not replace the native title with plain `textContent` merely to animate it.
- Native tooltip handling already tests `offsetWidth < scrollWidth` and sets `title` to the text. This supplies a useful fallback; hover scrolling must not prevent native selection, double click, context menus, or drag-and-drop.
- Rows are virtualized. A reused row is emptied with `oldDiv.innerHTML = ''`, then receives newly rendered cells. Row DOM IDs end in `-row-<index>` and are positional, not stable item identities.
- Delegate hover at the outer mount. Begin only when text actually overflows, and stop/reset on leaving, scrolling, resize, rerender/disconnection, view change, window unload, and plugin shutdown. Preserve inline styles you temporarily change. Avoid permanent per-row listeners or retained references to destroyed cells.

## Menus and safe tag writes

Sources: `zoteroPane.xhtml:978`; `zoteroPane.js:3720–3765`; `xpcom/data/item.js:1350–1389,2119–2131,2194–2205,4447–4515`; `xpcom/data/dataObject.js:674–694,761–788,827–866,891–1055,1199–1204`; `xpcom/data/items.js:803–826`; `xpcom/db.js:480–565`. All paths have prefix `chrome/content/zotero/`.

- Item popup ID: **`zotero-itemmenu`**. Append extension entries after existing children: the native builder indexes its built-in `childNodes` in a fixed order. Use `doc.createXULElement('menu' | 'menupopup' | 'menuitem' | 'menuseparator')`. Ignore bubbled `popupshowing` from nested popups (`event.target !== popup`). `win.ZoteroPane.getSelectedItems()` supplies the current selection.
- `item.isEditable('edit')` checks library permissions, imported attachment file permissions, and ownership of group annotations. **Feed libraries return editable from `DataObject.isEditable()`**, so also explicitly reject feeds for ordinary library status writes. Check that targets are real supported items, not deleted/trash objects; recheck permission when a queued action actually executes.
- `item.getTags()` returns cloned tag objects. `item.setTags(tags)` accepts strings or `{tag, type}` objects, cleans and sorts them, and only marks a change. A save is required. Unloaded tag data throws; load it before reading or writing when it is not already loaded.
- Existing item: `await item.save()` inside an existing transaction. Standalone save: `await item.saveTx()`. Never bypass edit checks, notifier updates, or sync metadata for this feature.
- Bulk pattern: serialize extension edit requests, snapshot/validate all targets, then `await Zotero.DB.executeTransaction(async () => { for (...) { item.setTags(nextTags); await item.save(); } });`. Reject/avoid preexisting unsaved item changes so the plugin does not accidentally save someone else's pending fields. Catch errors outside the transaction.
- **Database rollback does not fully restore every already-saved cached item.** Each successful save reloads its cached primary/tag data before the enclosing bulk transaction commits. A later save failure can roll back SQLite while earlier cached objects still show the failed update.
- After a failed bulk transaction, reload every touched existing item with `await item.reload(['primaryData', 'tags'], true)`. Also handle a failure before the save's internal recovery block: `_initSave()` is called outside that block, and tag reloading alone does not clear pending `_changedData.tags`. The installed internal helper `item._clearChanged('tags')` clears only tag change tracking; using it before reload is a narrowly scoped, source-verified recovery option. Do not call `_clearChanged()` without an argument because it discards unrelated pending changes. A dedicated injected-failure runtime test should verify both database and cached tags.

## Disposable-profile smoke strategy

`/Applications/Zotero.app/Contents/MacOS/zotero -help` exited successfully and advertises `--new-instance`, `--profile <path>`, `--headless`, `--marionette`, and `--remote-allow-system-access`. This leaf did not start a second Zotero instance; the integration owner runs the smoke test.

Use a freshly created temporary parent with separate empty `profile/` and `data/` directories, then launch the installed executable with:

```sh
/Applications/Zotero.app/Contents/MacOS/zotero \
  --new-instance --profile "$smoke_dir/profile" \
  -datadir "$smoke_dir/data" --marionette --remote-allow-system-access
```

Here `smoke_dir` must be the absolute path of the newly created disposable directory. Set a unique `marionette.port` in that profile's `user.js`; use only that port/process for test control. `--headless` can be added for API checks; visible native UI behavior requires a visible test window. Install the built XPI into this disposable profile only, seed artificial records, check registration/write/rollback/unload behavior, and close only the process started for the test.

Isolation depends on **both** flags: `xpcom/dataDirectory.js:57–83` gives command-line `Zotero.forceDataDir` precedence, and `xpcom/zotero.js:369–383` skips migration when that directory is forced. A new profile without an explicit data directory can inspect or migrate other profiles/default data directories. Do not reuse the user's live profile or library, change their profile list, or stop the running user instance.
