## Upstream documentation and evidence limits

The [GitHub README](https://github.com/MuiseDestiny/zotero-style) describes the feature gallery, tag-prefix conventions, view groups, graph view, and reader styling. Those features occupy different parts of Zotero and have different data prerequisites; they are not all expected to appear in the main table. Its update note directs users to Zotero's extension updater for minor releases.

The [GitHub master package metadata](https://raw.githubusercontent.com/MuiseDestiny/zotero-style/master/package.json) currently declares **2.6.7**, while this installed package is **6.0.73** and its manifest uses a Gitee update feed. The repository front page is consequently not a version-matched configuration guide or a complete current paid-entitlement matrix. The installed English localization also contains the older label “Pro Functions (free for a limited time)” at line 341; that string cannot establish this user's actual plan or trial status.

No persistent `.log` file was found in the profile or configured data-directory top level, and `~/Library/Logs/Zotero` was absent. The live settings report Pro fully unlocked, and the coordinator verified column/menu/control availability. The live error console was not inspected. The installed script exposes a read-only `addon.api.getProStatus()` accessor at line 35038, but invoking it was unnecessary to establish the app's displayed activation state and was not done. Individual protected operations, server billing records, citation-provider failures, and missing reading records were not tested.

Recommended settings steps supported by this evidence: show wanted columns through the column menu and save a View Group; configure the selected publication-data provider if IF/ranks are wanted; check colored Tags versus `#Tags` conventions and the lower-left nesting control; expand Graph View; and open a PDF to access reader styling and margin-annotation controls. The app already reports Pro fully unlocked, so repeating payment is not indicated by this evidence. Historical Quick Filtering and bold read/unread need separate current-version verification rather than an assumed settings fix. No settings were changed as part of this audit.
