# Style Custom 0.7.0 디자인·사용성 개선

문헌을 찾고, 근거를 읽고, 명시적으로 선택한 항목에 작업하는 순서가 보이도록 연구 작업 패널을 정리했습니다.

| 개선 영역 | 반영한 동작 |
|---|---|
| 정보 구조 | 17개 기능을 탐색·읽기·정리·도구로 그룹화하고 현재 메뉴와 문헌 범위를 상단에 표시합니다. |
| 시각적 우선순위 | 문헌 제목과 저자, 지표와 조작 버튼을 구분합니다. 읽기 상태의 색 막대와 선택 강조를 함께 사용합니다. |
| 화면 밀도 | 넓게/좁게 전환하고 선택한 밀도와 마지막 메뉴를 기억합니다. 좁게 해도 주요 조작을 숨기지 않습니다. |
| 필터 | 상세 필터를 접어 공간을 확보하고 적용 중인 조건을 개별 해제합니다. 부모 문헌 조건은 노트·주석·첨부 조회에도 적용합니다. |
| 빠른 이동 | 패널 안에서 ⌘/Ctrl+K로 기능을 검색하고 방향키·Enter로 이동합니다. Esc는 기능 찾기부터 닫고 기존 포커스를 돌려줍니다. |
| 선택 범위 | 현재 결과 밖의 선택도 개수로 알립니다. 연결 조작은 문헌 두 개 이상을 선택했을 때 활성화됩니다. |
| 저장 | 진행 중 상태와 버튼 비활성화를 제공합니다. 화면이 갱신돼도 같은 노트를 다시 제출하지 않습니다. 저장과 편집기 열기는 별도 조작입니다. |
| 상세·미리보기 | 많은 노트·주석은 개수와 첫 다섯 항목부터 표시하고 더 펼칩니다. 긴 텍스트를 펼칠 수 있고 지원하지 않는 첨부에는 열기 안내를 제공합니다. |
| 작은 화면·다크 모드 | 패널 너비·높이에 맞게 내비게이션과 조작 영역이 바뀝니다. 텍스트·선택·읽기 히트맵의 명암 대비를 계산해 검사했습니다. |

[오프라인 미리보기](design-preview.html)는 실제 Workbench 코드와 CSS를 사용하며 예시 문헌만 포함합니다. 기능 찾기·밀도·검색·상세 등을 눌러볼 수 있습니다. 파일 생성 및 초기 화면 DOM 구성을 Node에서 검증했고, 사용자의 브라우저나 Zotero를 실행하지 않았습니다. 별도 렌더러 스크린샷 또는 실제 Zotero 화면의 시각 검증을 했다는 의미는 아닙니다.

검증: Node/DOM/CSS **265개**, 임시 프로필 설치기 **11개** 통과. 이 중 작업 패널은44개, 스타일 검사는9개입니다. 기준은 **6개 충족, 미충족0개, 포기0개**입니다. 기존50개 원본 기능·7개 추가 흐름과18회 개선의 소스·테스트 연결도 다시 확인했습니다.

독립 리뷰에서 발견한 화면 갱신 후 중복 노트 제출과 늦게 끝난 이전 메뉴 이동의 설정·포커스 덮어쓰기는 실패를 재현한 뒤 수정했습니다. [UX 리뷰](ux-review-0.7.0.md), [디자인 토큰과 대비 측정](design-tokens-0.7.0.md)에 상세 근거가 있습니다. CSSOM이 지원하지 않는 container query 바깥 문법은 별도로 검사하고 내부 CSS를 동일한 규칙으로 파싱했습니다. 네이티브 렌더링 호환성 실측은 아직 하지 않았습니다.

XPI 런타임 파일18개를 소스와 바이트 단위로 대조했습니다. SHA-256: `61cdb8eb60330fa969fd4c5282709879dd43b9e044539dffb801f562a2398efd`.

기록 시점 설치 버전 **0.4.1**, 새 버전 업데이트 상태 `waiting-for-zotero-exit`. 이전0.6.0 대기 프로세스의 취소를 확인한 뒤0.7.0을 별도로 대기시켰습니다. 최대24시간 동안 Zotero가 완전히 종료되기를 기다리고 백업 후 교체하며 앱을 직접 종료하거나 실행하지 않습니다. 새 버전의 실제 활성화는 확인하지 않았습니다. [설치 상태](installation-status.json)의 실시간 상태 파일 경로를 참고하세요.
