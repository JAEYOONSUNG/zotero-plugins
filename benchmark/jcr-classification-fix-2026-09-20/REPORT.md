# Style Custom 0.50.3 — 저널 분류·순위 개선

JCR 실제 화면을 Aside로 확인하고, 저널 분류·필터·순위의 오류를 수정했다. 현재 플러그인의 분류는 OpenAlex이며, 이를 공식 JCR 분류로 표시하지 않는다. **JCR의 전체 카테고리별 데이터 연동과 이번 자체 분류·순위 계산의 수정은 구분한다.**

## 실제 JCR에서 확인한 구성

Aside의 내부 에이전트는 사용량 제한으로 시작되지 않아 직접 REPL 연결로 확인했다. JCR 홈페이지에서 Categories를 열고 Groups 화면과 전체 Categories 표를 확인했다.

- **21 Groups / 254 Categories**. 한 Category는 여러 Group에 포함된다.
- Categories 표의 열은 Category, Group, Edition, 저널 수, Citable Items, Total Citations, Median impact factor였다.
- 예를 들어 BIOCHEMISTRY & MOLECULAR BIOLOGY는 Biology & Biochemistry와 Chemistry 두 그룹에 속했다.
- 데이터 갱신일 표시는 **Jun 17, 2026**이었다.
- 내보내기 메뉴는 CSV/XLS를 제공하지만 CSV 선택 시 **Sign in to export** 대화상자가 나타났다. Clarivate 로그인 화면에서 자동완성은 나타나지 않아 사용자에게 로그인을 요청했다. 다운로드가 완료됐다고 주장하지 않는다.

[실제 화면 관찰 기록](jcr-browser-observations.json), [JCR 카테고리 화면](https://jcr.clarivate.com/jcr/browse-category-list).

공식 카테고리별 저널 소속·순위·Q 전체 파일은 아직 확보하지 않았다. 이번 수정은 이를 추정하거나 OpenAlex로 대체하여 공식값처럼 제공하지 않는다. 저널 화면에는 공식 JCR 카테고리 페이지로 이동하는 버튼을 추가했다.

## 확인된 오류의 수정

| 항목 | 수정 전 | 수정 후 |
| --- | --- | --- |

| Nature Methods의 캐시 | Biophysics 두 개로 분류가 바뀌고 순위는 Molecular Biology 기준 | 네 분류를 유지하며 표·필터·상세·순위 기준 통일 |

위 Genetics 건수는 전체 번들 레지스트리를 실제 필터 함수에 넣어 확인한 수치다. 선택한 서재와 캐시가 반영된 모든 화면에서 같은 건수가 나온다는 뜻은 아니다.

추가로 서로 다른 ISSN의 다음 두 저널 쌍이 이름 정규화로 합쳐지는 문제를 수정했다. 정확한 제목을 우선하고, 모호한 정규화 이름은 임의로 하나를 선택하지 않는다. 각 저널의 분류·JIF·순위는 독립적으로 유지된다.

- Space-science & Technology / Space Science and Technology
- Journal of Computer Science and Technology / Journal of Computer Science & Technology

현재 표시된 JIF가 같으면 공동 순위를 부여하고 다음 순번을 건너뛴다. 이 규칙을 사용해도 모집단이 OpenAlex 주제 분류인 이상 공식 JCR 순위가 되는 것은 아니다.

## 표시와 데이터 출처

기존의 ‘전체 JCR’, ‘JCR 순위’처럼 과도한 의미를 주던 이름을 저장 목록·자체 비교로 구분했다. 분야 이름과 계산 결과의 출처는 OpenAlex 및 저장된 JIF임을 표시한다. 카테고리 정보가 없는 기존 단일 Q는 **카테고리 미확인** 상태로 남기고, 공식 카테고리별 Q처럼 사용하지 않는다.

저장된 분류가 있는 저널은 동일한 분류를 표·상세·필터·자체 순위에 사용한다. 캐시는 분류가 없는 저널의 보완에 사용하며, 제공된 유효 경로를 중복 없이 사용한다. 프로필·지표·레지스트리 변경은 같은 문헌 ID를 유지해도 화면 캐시를 갱신한다. 저장된 레지스트리 JIF가 있으면 오래된 문헌별 값보다 우선하여 표시와 순위 계산의 연도를 맞춘다.

기존 22,594종의 저널 행과 분류 경로는 그대로 보존하고 출처 메타데이터를 추가했다. 기존 분류는 수집일·분야 ID가 보존되지 않은 상위 8개 주제/최대 4개 경로 자료이며, 새로 전수 조회한 것으로 표시하지 않는다. 기존 분류 미확인 저널 413종도 확인 없이 채우지 않았다.

새 분류 생성 도구는 모든 반환 주제와 식별자·가중치를 보존하고, 저널의 모든 ISSN을 사용한다. 배열 순번에 의존하는 구형 재개 자료의 병합은 거절한다. 새 캡처는 안정된 저널 식별자와 레지스트리 지문을 사용하며, 불완전·미확인 상태와 기존 분류의 출처를 구분한다. **이번 작업에서 실제 OpenAlex 전수 수집은 실행하지 않았다.**

## 검증 방식

전체 레지스트리의 원본 행에서 기대 분야·멤버십을 독립적으로 만든 후, 실제 제품 함수의 결과와 비교했다. 제품이 반환한 결과만 검사하는 방식으로 누락을 놓치지 않도록 전체 그룹 삭제와 멤버 한 개 삭제를 실패 대조군으로 사용했다.

[전수 검증 결과](verification.json)는 **22,594개 저널, 277개 전체 경로 그룹, 138,863건의 분야 소속**을 검사한다. 그룹·멤버 누락, 모집단, 동점 순위, Q, 반올림, 경로 필터, 캐시 분류와 JIF 연도를 검증한다. 이 숫자는 JCR 카테고리 개수나 공식 JCR과의 일치율이 아니다.

UI 검사는 실제 DOM 이벤트로 같은 이름의 여섯 분야, 불가능한 경로, 선택 분야별 순위·정렬, 캐시 갱신, 혼합 연도 표기를 확인한다. 생성기·설치기 검사는 임시 자료와 가짜 프로필에서 수행한다. 사용자 Zotero 창이나 Run JavaScript 창을 열지 않았다.

## 설치 원칙

검증된 설치 파일과 현재 설치본의 SHA-256을 고정한다. 다른 업데이트가 같은 버전이라도 다른 내용으로 바뀌면 설치를 중지한다. 설치기의 원본 파일 교체 경합과 공유 설정 변경 감지도 보완했다.

Zotero가 실행 중이면 강제로 종료하거나 즉시 교체하지 않고 정상 종료를 기다린다. 파일 설치, 다음 시작 시 활성화, 실제 실행 검증을 별도로 기록한다. 협조하지 않는 임의의 외부 쓰기를 운영체제 수준에서 완전히 배제한다는 보장은 하지 않는다.

## 최종 확인

- 자동 검사: **Node 661개 / 데이터 생성기 20개 / 설치기 28개 통과**, 실패·건너뜀 0개. 최초 전체 검사에서 발견된 개선 기록의 구버전·변경된 테스트 이름 참조도 갱신했다.
- 빌드: **Style Custom 0.50.3**, 설치 파일 SHA-256 `54bd5b52768a005d2455d857c581251890409389bdd889fd76ca4d67478d0d0d`. [빌드·대기 상태 확인 기록](build-receipt.json).
- 기존 설치본과 다른 파일은 이번 수정에 해당하는 8개뿐이며, 나머지 파일은 기존 설치본과 동일하다. 모든 설치 파일 구성 요소는 최종 작업 소스와 일치했다.
- 확인 시점 Zotero는 실행 중이므로 **현재 설치 버전 0.50.2, 수정본 0.50.3은 정상 종료 후 설치 대기**다. 대기 프로세스가 살아 있고 상태 파일을 갱신하는 것을 확인했다. 앱을 강제 종료하지 않았다.
- 다음 실행에서의 활성화·실제 화면 실행 검증은 아직 하지 않았다. JCR 공식 데이터 내보내기도 Clarivate 로그인 대기이며, 전체 공식 자료 연동 완료로 보고하지 않는다.
- Unlazy 완료 기준 **15개 충족 / 미충족 0개 / 포기 0개**. 이는 위 범위의 수정·검증·설치 준비 완료를 뜻한다.

실시간 설치 상태: `build/jcr-classification-fix-20260920/install-status.json`. 대기를 취소하려면 같은 폴더에 `cancel-install` 파일을 만들면 된다. 다른 설치본으로 변경된 경우 자동으로 기준을 바꾸어 덮어쓰지 않고 작업을 중지한다.
