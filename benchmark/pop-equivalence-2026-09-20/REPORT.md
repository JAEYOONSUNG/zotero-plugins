# ZotPoP 0.38.0 — PoP 원본 검색과 저자 검색 검증

2026-09-20에 0.38.0을 빌드하고 실제 Zotero 프로필에 설치했다. 저자 검색 탭에서 Google Scholar 프로필 또는 ORCID 공개 기록의 실적을 불러올 수 있다. 논문 검색에는 설치된 Publish or Perish의 원본 검색 엔진을 명시적으로 선택하는 모드를 추가했다.

## 동등성의 범위와 측정 결과

**같은 PoP 스냅샷을 사용하는 원본 출력 보존은 5/5 사례, 총 1,062행에서 일치했다.** 행 수·순서·중복·원본 순위·모든 JSON 필드의 값과 자료형·필드 유무를 검사했고, ZotPoP 표시용 변환도 별도로 검사했다. 다른 시점에 새로 조회한 두 결과가 항상 같다는 뜻은 아니다. 최신 별도 새 조회 비교는 **3/4 통과**이며, 실패한 사례도 그대로 보존했다.

| 사례 | 행 수 | 동일 스냅샷 출력·표시 변환 | 별도 새 조회 간 출력 비교 |
| --- | ---: | --- | --- |
| Crossref `geobacillus`, 최대 1,000건 | 1,000 | 통과 | 실행하지 않음 |
| PubMed 알려진 논문 제목 | 1 | 통과 | 통과 |
| Google Scholar 알려진 논문 제목 | 1 | 통과 | 통과 |
| Google Scholar 저자 조건 논문 검색 | 30 | 통과 | 통과 |
| Crossref `geobacillus`, 인용 수 내림차순 | 30 | 통과 | 실패: 인용 0회인 두 행의 순서 교환 |

마지막 사례는 0부터 세는 위치 23·24의 DOI `10.1601/ex.5027`과 `10.7717/peerj.2714/table-2`가 두 번의 새 PoP 실행 사이에서 교환됐고, 각 DOI의 원본 순위도 22·23 사이에서 바뀌었다. 순서와 순위를 제외한 값 및 결과 집합은 같지만 원본 전체 일치 기준에는 실패한다. ZotPoP는 받은 순서와 순위를 그대로 유지한다. 이 결과를 숨기기 위해 정렬 기준이나 합격 조건을 바꾸지 않았다.

실제 제품 경로 `Sources.search → PoP bridge → pop8query`로 후보를 수집했다. 기준 결과는 인자를 별도로 구성한 독립 프로세스에서 수집했다. 동일 스냅샷 검사는 후보 실행이 만든 PoP 캐시를 별도 프로세스가 읽고, 전후 캐시 SHA-256과 생산 실행 ID를 대조한다. 캐시를 새 검색으로 표시하거나 알 수 없는 원래 수집 시간을 만들어내지 않는다. 자세한 조건·실행 ID·소스 해시·실패 차이는 [측정 결과](fidelity-summary.json)에 있다.

이 검증이 입증하는 것은 **명시적으로 선택한 PoP 원본 엔진의 출력 보존**이다. 별도로 구현한 검색 색인의 보편적 동등성, 모든 제공자의 접근 가능성, 모든 결과의 정확성이나 완전성을 입증하지 않는다. 기존 엄격한 서지 품질 검사도 유지했다. PoP 자체가 저자를 생략하거나 제목을 제공하지 않는 경우는 출력이 같아도 정확성 미확인으로 남는다.

## 원본 검색 사용법과 동작

논문 검색의 엔진에서 **Publish or Perish 원본 검색**을 선택하고 검색원을 고른다. Google Scholar, Scholar 저자 목록·프로필·인용 문헌, Crossref, PubMed, OpenAlex, Semantic Scholar, Harzing 데이터, Lens, Scopus, Web of Science 세 경로를 포함한 14개 CLI 경로를 연결했다. 위 표에 명시한 경로와 아래 프로필 경로를 실제 조회했다. 나머지 경로의 서비스 접근은 해당 계정·키·구독 및 PoP 지원 상태에 달려 있으며, 전부 실조회했다고 주장하지 않는다.

기본값은 PoP 앱의 기존 프로필을 사용한다. 원본 필드 검색과 원본 검색식, 출력 정렬, 새 조회/PoP 캐시 읽기를 선택할 수 있다. 이 모드는 중복 제거·추가 필터·인용 보강·임의 결과 자르기를 수행하지 않는다. 중복 행도 각각 선택할 수 있고, 검색 기록은 원본 순위와 메타데이터를 보존한다. **PoP 원본 JSON 복사**로 받은 원본 배열을 원래 순서대로 복사한다. 로컬 표 정렬과 원본 순위는 구분한다.

공식 검색원 및 CLI 사양: [PoP command line](https://harzing.com/resources/publish-or-perish/command-line), [PoP data sources](https://harzing.com/resources/publish-or-perish/manual/using/data-sources).

## 이전 Crossref 차이의 조사 결과

이전 비교의 고유 식별자 누락 15개를 각각 조사했다. 당시 PoP가 받은 실제 HTTP 페이지를 현재 직접 검색 경로에 재생하면 **986개 고유 DOI 모두**, 누락됐던 15개를 포함하여 반환한다. 1,000행 중 중복 14행은 이미 제공자 응답에 존재했다. 이 가운데 11개는 페이지 간 관련도 점수도 달랐다. 따라서 모든 차이를 단순한 동점 정렬 문제로 설명할 수 없다. 당시 후보 HTTP 원문을 보관하지 않았으므로 각 누락의 역사적 원인을 확정할 수는 없고, 같은 입력에서 ZotPoP가 해당 식별자를 버리는 현상은 재현되지 않았다.

메타데이터 충돌 30개 중 26개는 PoP가 기관·단일 이름 저자를 생략한 차이이며 직접 검색은 제공된 저자를 보존한다. 4개는 비교기의 `<scp>` 서식 처리 누락을 수정했다. 미확인 필드 51개는 발행 연도 없이 등록 연도를 사용한 PoP 기록 47개, 편집자를 저자로 표시한 2개, 제목 없는 연구비 기록 2개로 분류했다. 직접 검색의 발행일이나 저자를 원본과 같게 만들려고 잘못 덮어쓰지 않았다. [개별 DOI와 근거](CROSSREF-DIAGNOSIS.md), [재생 측정](crossref-diagnosis.json).

Scholar도 잘린 저자 목록과 검증할 수 없는 이름 조건을 그대로 표시한다. PoP를 자기 자신과 비교해도 기존 엄격 검사에서 Crossref의 제목 없는 기록과 Scholar의 불완전한 저자 정보는 미확인으로 남는다. 출력 보존 검사는 이 품질 검사를 대체하지 않는다.

## 저자 전용 검색

상단 **저자 검색** 탭에서 검색원을 고른다.

- **Google Scholar:** 이름으로 프로필 목록을 찾거나 프로필 URL/ID를 입력하고 실적을 불러온다. 자동/이름/프로필 입력 구분이 있으며, 이름으로 논문 찾기는 별도 동작이다. 이름으로 찾은 논문은 동일 인물의 실적으로 확정하지 않는다.
- **ORCID:** ORCID iD 또는 프로필 URL로 공개 프로필을 확인하고 등록된 공개 실적을 불러온다. 체크섬이 틀린 iD는 거절한다. 이름 기반 ORCID 전체 레지스트리 검색은 이번 구현에 포함하지 않았다.

실제 설치한 Zotero에서 ORCID `0000-0001-8277-5907`의 **Sheila Ingemann Jensen 공개 실적 26건**, Scholar `dsdG3ewAAAAJ`의 **실적 10건(설정한 한도)**을 조회했다. 별도 Scholar 이름 조건 논문 검색은 5건을 반환했고, 신원 미확인 상태를 유지했다. [서비스 조회 기록](authors-live-summary.json), [이름 검색 기록](author-name-live.json), [설치된 Zotero 검증](native-verification.json).

현재 환경의 Scholar 이름→프로필 목록 조회는 서비스 오류(exit 3)를 반환했다. 이 실패를 재시도나 우회로 숨기지 않았다. 공식 안내에 따르면 Scholar 프로필 검색은 Google 계정 로그인이 필요하다. 프로필 ID를 직접 지정한 실적 조회는 위와 같이 성공했다. [PoP Google Scholar Profiles 안내](https://harzing.com/resources/publish-or-perish/manual/using/data-sources/google-scholar-profile).

ORCID 결과는 해당 기록에 공개 등록된 실적이다. 전체 연구 경력이나 완전한 공저자 목록을 보장하지 않는다. 인용 수를 제공하지 않으므로 h-index를 0으로 꾸미지 않고 지표를 계산할 수 없다고 표시한다. [ORCID 공개 기록 읽기](https://info.orcid.org/documentation/api-tutorials/api-tutorial-read-data-on-a-record/), [레지스트리 검색 API](https://info.orcid.org/documentation/api-tutorials/api-tutorial-searching-the-orcid-registry/).

검색원별 저자 입력과 선택, 검색 기록을 보존하며 논문 검색 탭으로 돌아오면 이전 논문 조건과 결과가 복원된다. 중지·탭 전환 후 늦게 도착한 요청이 다른 결과를 덮지 않도록 검증했다.

## 회귀 및 설치 검증

- 오프라인 테스트 **347개 통과, 실패·건너뜀 0개**. 검색 의미, 깊은 조회, 원본 보존, 저자 식별, 취소, 기록, 열 드래그, hover 전용 움직임을 포함한다.
- 원본 비교기는 행 추가·누락·순서·순위·인용 수·식별자·저자 속성·필드 유무·오래되거나 불완전한 자료를 변조한 음성 대조군에서 실패하는지 검사했다.
- 실제 Zotero에서 0.38.0 설치, 원본 검색원 14개 표시, 원본 30행의 순위·개별 키·기록 복원, JSON 복사 버튼, 저자 검색 및 논문 검색 상태 복원을 확인했다. 검증 후 사용자의 기존 검색 상태를 복원했다.
- [설치 대조 기록](install-receipt.json)에서 XPI의 JavaScript·화면 마크업·CSS가 최종 작업 소스와 바이트 단위로 같음을 확인했다. 작업 폴더의 별도 툴바 아이콘 변경은 이 설치본에 포함되지 않았다. 원본 공개 스냅샷·실제 요청·로컬 재생 자료는 서로 구분한다.

Unlazy 완료 기준은 **충족 17개, 미충족 0개, 포기 1개**다. 포기한 `GATES:E1`은 과거 Crossref 누락 각각의 실제 원인 확정이다. 당시 후보 응답 원문이 없어 복구할 수 없는 증거를 요구하므로 완료로 처리하지 않았다. 구현·설치·현재 조회 검증은 끝났으며, 이 과거 원인 규명과 무조건적인 전체 검색 동등성은 완료됐다고 주장하지 않는다.

재현 명령은 `npm run test:offline`, `node scripts/pop-equivalence-diagnose.mjs`, `node scripts/pop-equivalence-verify.mjs`, `node scripts/pop-equivalence-authors-live.mjs`이다. 실조회 스크립트는 로컬 PoP 실행 파일과 서비스 접근이 필요하다. 원본 실행별 캡처와 로그는 로컬 `build/pop-equivalence-20260920/`에 보관한다. 저자 서비스의 첫 실조회 이후 추가한 모호한 입력 구분은 최종 단위 검사와 설치본 검증으로 확인했다.
